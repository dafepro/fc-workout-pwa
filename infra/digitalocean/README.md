# ZoomiGo infrastructure

This OpenTofu module creates the DigitalOcean project, Droplet, assigned Reserved IP, Cloud Firewall, monitoring/backups, resource alerts, global readiness check, proxied Cloudflare API record, and protected D1 analytics database. Secret-free cloud-init prepares the exact pushed release. The Worker custom domain and application release remain in `deploy/release/`.

No secrets belong in `.tf`, `.tfvars`, cloud-init, or Git. `DIGITALOCEAN_TOKEN` and `CLOUDFLARE_API_TOKEN` live only in the operator's shell environment (local fallback) or the GitHub `production` environment secrets (`.github/workflows/infra.yml`). `cloudflare_account_id` is a non-secret identifier supplied from the existing `CLOUDFLARE_ACCOUNT_ID` environment secret in CI. Terraform state lives remotely in a dedicated Cloudflare R2 bucket via the `s3` backend in `versions.tf`; nothing encrypts or commits state locally. `use_lockfile = true` gives native state locking without a separate lock table. Destructive resources use `prevent_destroy`, and there is intentionally no automated destroy command.

The primary operator procedure is triggering the `infra.yml` GitHub Actions workflow's `plan` action (which runs `tofu plan`), reviewing the uploaded plan artifact, then triggering `apply` against that exact reviewed plan. `provision.sh`/`provision.mjs` remain as a documented local incident fallback for when GitHub Actions itself is impaired; see `docs/PRODUCTION_RUNBOOK.md`. Do not invoke raw `tofu apply`.
